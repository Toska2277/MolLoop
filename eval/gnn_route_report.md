# 模型升级路线实验记录（C 路线：GNN）

> 记录时间：2026-11-18 凌晨
> 结论先行：**C 路线（图神经网络）在本机环境下未能完成有效训练**，原定 0.05 eV 目标未达成；
> 已给出可复现的替代结果：指纹 + 三维构型特征融合模型 **MAE 0.1522 eV（R² 0.9672）**，比现有 2D 描述符方案（0.1622）再降 **6.2%**。

## 一、目标与预设

| 路线 | 做法 | 预期 MAE | 状态 |
|---|---|---|---|
| A | 2D 描述符 + 树模型堆叠 | 0.15 | 已完成，0.1555 |
| B | DFT 三维描述符 + 树模型 | 0.10–0.12 | 未按原计划（数据源不可达，改用自生成构型） |
| C | SchNet / GNN | 0.03–0.05 | **受阻**，见第三节 |

## 二、环境实测

| 项目 | 实测结果 |
|---|---|
| GPU | NVIDIA GeForce RTX 4060 Laptop，8188 MiB，驱动 610.62，CUDA 可用 |
| 内存 | 16 GB 总，空闲约 2.2–3.2 GB |
| Python | 3.13.18（项目 .venv） |
| PyTorch | 官方 CUDA 轮子 `torch-2.14.1+cu126-cp313-win_amd64.whl` **2602.8 MB** |
| 下载实测 | download.pytorch.org ≈ 0.11 MB/s；南大镜像单连接 0.24–1.0 MB/s，8 线程分段反而降到 0.02 MB/s；清华/中科大/北外/北大镜像不可达；华为云 pypi 镜像只提供 CPU 轮子 |
| 结论 | 2.6 GB 轮子在本机网络下需 1.5–5 小时且多次中断，**今夜无法完成**；改走 CPU-only（`torch 2.15.0+cpu`，126.7 MB，3 分 22 秒装好） |

## 三、C 路线失败的两个原因（都是硬约束，不是调参问题）

### 1. 算力：CPU 训练速度不够

用 `train/bench.py` 实测（本机 8 核，torch 线程 6）：

| 配置 | 每步耗时 | 吞吐 |
|---|---|---|
| dim=64, batch=64 | 60 ms | 1069 分子/秒 |
| dim=96, batch=128（实跑） | — | 约 460 分子/秒（含验证） |

SchNet（3 交互层、96 维、cutoff 5 Å、3 折 × 15 轮）单轮 **201 s**，5 折 × 15 轮需 **4.2 小时**。
实际只跑到 fold0 第 7 轮（`logs/schnet_run1.out`）：

| 轮 | val MAE (eV) |
|---|---|
| 1 | 0.4462 |
| 2 | 0.3677 |
| 3 | 0.3242 |
| 4 | 0.3059 |
| 5 | 0.2961 |
| 6 | 0.2822 |
| 7 | 0.2628 |

第 7 轮 0.2628 仍高于 2D 描述符模型 0.1622，按收敛速度推算 15 轮只能到 0.20–0.22，**追不上现有模型**，故终止。

### 2. 数据：QM9 原始 DFT 几何全部不可达

| 源 | 结果 |
|---|---|
| Figshare（QM9 原始 xyz，官方） | HTTP 202，0 字节（反爬）；api.figshare.com 返回 403 |
| deepchem S3 镜像 | HTTP 403 |
| Zenodo revQM9 / QCArchive | DNS 无法解析 |
| HuggingFace | 连接超时 |
| GitHub | 约 11 KB/s，85 MB 需 2 小时以上 |

因此三维构型改用 **RDKit ETKDGv3 嵌入 + MMFF94 优化** 自行生成（`train/make_geom.py`，48 分片、6 进程并行、约 35 分钟，132,024/133,802 成功，成功率 98.7%，失败 1,778 个为复杂笼状/稠环分子）。
**这意味着几何是分子力学级别，不是 DFT 级别**；用它训练 SchNet 本身就丢掉了 3D 信息的精度优势，是 C 路线精度上不去的第二个原因。

## 四、实际交付的替代结果

### 4.1 混合特征模型（`train/hybrid.py`）

特征构成：222 维 2D 描述符 + Morgan（r=2, 2048 位计数）+ MACCS（167 位）+ 三维构型特征 31 维（库仑矩阵特征值前 16、距离分布直方图 12、PMI 2、平均回转半径 1）。
模型：XGBoost `hist`，max_leaves 64，900 轮，5 折 OOF。

| 折 | MAE (eV) |
|---|---|
| 0 | 0.1679 |
| 1 | 0.1666 |
| 2 | 0.1673 |
| 3 | 0.1648 |
| 4 | 0.1679 |
| **OOF** | **0.1669**（RMSE 0.2425，R² 0.9648） |

单独看不如 RF（0.1622），但误差结构不同，适合融合。

### 4.2 融合模型（`train/blend.py`）

按 0.05 步长搜索权重，最优 **0.70 × 堆叠（RF+ET+XGB+岭） + 0.30 × 混合特征**：

| 指标 | 数值 |
|---|---|
| MAE | **0.1522 eV** |
| RMSE | 0.2342 |
| R² | 0.9672 |
| MedAE | 0.1077 |
| n | 133,802 |

与之前版本对比：

| 版本 | MAE | R² |
|---|---|---|
| 单 RF（页面当前使用） | 0.1622 | 0.9627 |
| 堆叠（RF+ET+XGB+岭） | 0.1555 | 0.9646 |
| 混合特征 XGB | 0.1669 | 0.9648 |
| **融合（0.7 堆叠 + 0.3 混合）** | **0.1522** | **0.9672** |

## 五、如果要把 C 路线做成的条件（写进方案书"后续计划"）

1. **GPU 可用**：需要 `torch+cu126` 轮子离线包（2.6 GB），或用有公网带宽的机器下载后拷入；一台能跑 CUDA 的训练机可将单轮训练压到 10–20 秒，5 折 × 30 轮约 30 分钟。
2. **DFT 级几何**：拿到 QM9 原始 xyz（Figshare 202 问题需换网络或经他人中转），或用 xTB/GFN2-xTB 重新优化 MMFF 构型（133k 分子约 6–10 小时）。
3. 若两者都满足，SchNet 在 QM9 gap 上可到 0.05 eV 量级（文献口径），但**覆盖范围仍限 9 个重原子以内**，要覆盖阿司匹林需 PCQM4Mv2（约 11 GB），本机网络不具备条件。

## 六、结论口径（对外表述建议）

- 不写"我们用了 GNN 达到 0.05"，写"我们尝试了 GNN 路线，受本机算力与公开数据源可达性限制，在 15 轮内 val MAE 0.26 eV 未达预期，如实记录并给出替代方案"。
- 主打指标用**融合模型 0.1522 eV / R² 0.9672**，并说明这是 2D 描述符 + 指纹 + 三维构型特征的可复现结果。
- 这一条本身就是"数据与结果可靠性"（25 分）的加分材料：**失败实验如实记录 + 口径一致 + 可复现**。
